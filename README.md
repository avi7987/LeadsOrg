# מערכת ניהול לידים מוואטסאפ · איה

מערכת שקולטת הודעות נכנסות בוואטסאפ של איה, מזהה אוטומטית לקוחה פוטנציאלית חדשה,
אוספת ממנה פרטים דרך פופ-אפ, ומרכזת את כל הלידים בדשבורד לניהול.

> **המספר של איה נשאר כמו שהוא.** המערכת מתחברת כ"מכשיר מקושר" (כמו וואטסאפ-ווב),
> אז איה ממשיכה להשתמש בטלפון שלה רגיל לגמרי.

---

## מבנה הפרויקט

```
Leads APP/
├── leads-app.html      ← הדשבורד של איה (הממשק שכבר בנינו)
├── db/
│   └── schema.sql      ← סכימת בסיס הנתונים (מריצים פעם אחת ב-Supabase)
└── worker/             ← ה"מוח" — מאזין לוואטסאפ ומזהה לידים
    ├── src/
    │   ├── index.js    ← חיבור לוואטסאפ
    │   ├── logic.js    ← לוגיקת הזיהוי (מהאפיון)
    │   └── db.js       ← גישה ל-Supabase
    ├── package.json
    └── .env.example
```

## שלושת הרכיבים

| רכיב | מה זה | איפה רץ |
|---|---|---|
| **Supabase** | בסיס הנתונים + התחברות של איה | ענן (חינם בהתחלה) |
| **Worker** | מאזין לוואטסאפ ומריץ את לוגיקת הזיהוי | שרת קטן שרץ תמיד |
| **דשבורד** | הממשק שאיה עובדת בו | דפדפן / אירוח סטטי |

## התקנה — צעד אחר צעד

### 1. Supabase (בסיס הנתונים)
1. נכנסים ל-[supabase.com](https://supabase.com) ופותחים פרויקט חדש (חינם).
2. נכנסים ל-**SQL Editor**, מדביקים את כל התוכן של [`db/schema.sql`](db/schema.sql) ומריצים.
3. נכנסים ל-**Project Settings → API** ומעתיקים:
   - `Project URL`
   - מפתח `service_role` (סודי!)

### 2. Worker (המוח)
```bash
cd worker
npm install
cp .env.example .env      # ואז ממלאים את SUPABASE_URL ו-SUPABASE_SERVICE_ROLE_KEY
npm start
```
בהפעלה הראשונה יופיע **קוד QR** בטרמינל. בטלפון של איה:
**וואטסאפ → הגדרות → מכשירים מקושרים → קישור מכשיר → סורקים את הקוד.**

מרגע זה המערכת מאזינה. החיבור נשמר, אז לא צריך לסרוק שוב בכל הפעלה.

### 3. איפה מריצים את ה-Worker כל הזמן
ה-Worker חייב לרוץ 24/7 (הוא מחזיק את החיבור החי). אפשרויות זולות:
- **Railway** / **Render** — פשוט, מ-~5$ לחודש.
- **droplet ב-DigitalOcean** / VPS קטן — ~5$ לחודש.
- **רספברי-פיי** בבית של איה — עלות חד-פעמית, בלי מנוי.

## איך המערכת מחליטה (מתוך האפיון)

לכל הודעה נכנסת:
1. **מספר שמור** באנשי הקשר → מתעלמים לחלוטין.
2. **פרסום ממומן** (הודעת פתיחה מזוהה) → ליד אוטומטי מתויג "פרסום", בלי פופ-אפ.
3. **שיחה ראשונה, מספר לא שמור** → בודקים את 3 ההודעות הראשונות (בתוך שעה) מול מילות המפתח.
4. **נמצאה מילת מפתח** → נשלח פופ-אפ עם שאלות, והתשובות נכנסות כליד חדש.
5. **לא נמצאה מילת מפתח ב-3 הודעות / עברה שעה** → לא נוצר ליד (אפשר להוסיף ידנית מהדשבורד).

מילות המפתח, שאלות הפופ-אפ וטקסט זיהוי הפרסום — כולם נערכים ממסך ההגדרות בדשבורד.

## ⚠️ חשוב לדעת

- החיבור מבוסס ספרייה **לא רשמית** (`whatsapp-web.js`). זו הדרך היחידה להישאר על המספר הקיים
  ולתת לאיה להמשיך להשתמש באפליקציה — אבל היא **נגד תנאי השימוש של Meta** ויש סיכון תיאורטי לחסימת המספר.
  בפועל עסקים קטנים רבים מריצים כך שנים; המערכת מתנהגת "אנושי" (תגובה אחת ללקוחה אמיתית, בלי ספאם) כדי למזער סיכון.
- מפתח ה-`service_role` הוא סודי — רק ב-Worker, לעולם לא בדפדפן/בדשבורד.
